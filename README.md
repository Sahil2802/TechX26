# AquaGrid

Water network orchestration agent (TechX Dubai 2026, Track 5). Python code decides what is safe, the LLM only
explains, and a human operator approves every valve or setpoint change. See `PLAN.md` for scope.

## Setup

Needs [uv](https://docs.astral.sh/uv/) (it installs Python 3.12 if missing).

```bash
uv sync                    # install dependencies
cp .env.example .env       # then add keys (see below)
uv run streamlit run app.py
```

Open http://localhost:8501. The demo database is built automatically on first launch.

## LLM keys (optional)

Set `GROQ_API_KEY` and/or `GEMINI_API_KEY` in `.env`, or run [Ollama](https://ollama.com) locally.
Without any of these, the dashboard still works and the brief is generated by code only. The
"Scripted attacker" model option needs no key.

Set `OPERATOR_TOKEN` in `.env` to require a token for approve/reject/revert.

## Try it

Pick a scenario, click **Load scenario**, then **Run agent**:

| Scenario | Shows |
|---|---|
| `baseline` | Normal day, nothing to flag |
| `peak_2pm` | S4 leak found, faulty sensor quarantined, peak-tariff throttle vetoed by the reserve floor |
| `s4_drift` | Drifting sensor treated as a fault, not a leak |
| `attack` | With Model = "Scripted attacker": injected valve command is blocked by the gateway |

## Terminal and tests

```bash
uv run python -m aquagrid.cli run peak_2pm
uv run python -m aquagrid.cli run attack --attack
uv run pytest -q
```
