# AquaGrid

Water network orchestration agent for a coastal water authority (TechX Dubai 2026, Track 5).
It schedules desalination around the electricity tariff and detects leaks, with hard read/write
separation and safety floors that always beat cost savings.

| Who | Does | Never does |
|---|---|---|
| **Code** | Sensor checks, leak vs fault classification, reservoir maths, every limit, every write | Trust the LLM's claims |
| **LLM** | Correlates tariff and demand, interprets signals, drafts the operator brief | Write to the DB, call a valve or setpoint function, approve anything |
| **Human operator** | Approves, rejects or reverts every valve or plant setpoint change | n/a |

All data is synthetic (SQLite, generated by `aquagrid/seed_data.py`). The simulated clock is
`2026-11-20 14:00`, the start of the peak tariff.

## Quick start

Needs [uv](https://docs.astral.sh/uv/) (it installs Python 3.12 if missing) and Node 20+ for the frontend.

```bash
uv sync                                      # Python dependencies
cp .env.example .env                         # then edit (see Configuration)
npm --prefix frontend install                # frontend dependencies
npm --prefix frontend run build              # builds frontend/dist
uv run uvicorn aquagrid.web:app              # serves the console and the API
```

Open http://localhost:8000. The demo database is built on first launch.

Frontend development with hot reload: run the uvicorn command above, then `npm --prefix frontend run dev`
and open http://localhost:5173 (it proxies `/api` to port 8000).

## Demo scenarios

In the console, pick a scenario, click **Load scenario**, then **Run agent**.

| Scenario | What it shows |
|---|---|
| `baseline` | Normal day, nothing to flag (no false positives) |
| `peak_2pm` | Real S4 leak localised; faulty sensor quarantined, not treated as a leak; peak-tariff throttle vetoed because the reservoir would fall below the floor during an algal-bloom warning |
| `s4_drift` | A drifting then flatlined sensor is classified as a sensor fault, not a leak |
| `attack` | Prompt injection in a bloom alert. With Model = "Scripted attacker", the injected valve command is blocked by the gateway and nothing changes without operator approval |

These behaviours are also covered by automated tests (`tests/test_scenarios.py`).

## How it stays safe

1. **Three tools only** are exposed to the LLM: `read_network_telemetry()` and
   `read_tariff_and_quality_feeds()` (both read-only, SQLite opened read-only), and
   `stage_gated_valve_or_setpoint_action()`, the only write path.
2. **Staging never moves anything.** It validates the request against a strict schema (unknown
   fields such as `approved=true` are rejected), checks the target allowlist and a per-run cap, runs
   the guards, then queues a `PENDING_APPROVAL` row.
3. **Safety floors are hard-coded** in `aquagrid/config.py`, not in prompts. The reservoir must stay
   at or above 35% (40% while a bloom is active or the intake sensor is untrusted), checked on the
   *projected* level after the action. Floors override tariff savings.
4. **Every change needs a human.** There is no auto-approve path. On approval the gateway
   re-validates against fresh state and applies the change, the status and the audit record in one
   transaction. A rejected action changes nothing.
5. **Sensors are checked first**: flatline, drift, impossible values and mass balance. Faulty sensors
   are quarantined and excluded from every decision.
6. **Untrusted text** from feeds and telemetry is sanitised and schema-validated, never executed.
7. **Append-only audit log** (`audit_log` table) of every input, tool call, guard result, decision
   and approver.

## Configuration

Set in `.env` (gitignored). Never commit real keys.

| Variable | Purpose | Default |
|---|---|---|
| `GROQ_API_KEY`, `GEMINI_API_KEY` | Cloud LLM providers (optional) | unset |
| `LLM_CHAIN` | Provider order; providers without a key are skipped | `groq,gemini,ollama` |
| `GROQ_MODEL`, `GEMINI_MODEL`, `OLLAMA_MODEL` | Model ids | see `.env.example` |
| `ADMIN_TOKEN` | Admin token: all plants, may switch plant | unset |
| `PLANT_A_TOKEN`, `PLANT_B_TOKEN` | Plant-scoped tokens: that plant only | unset |
| `OPERATOR_TOKEN` | Legacy name, still works as the admin token when `ADMIN_TOKEN` is unset | unset |
| `AQUAGRID_DB` | Plant A SQLite path (plant B's file sits beside it, see Plants) | `data/aquagrid.sqlite` |

- **No keys:** the console still works and the brief is generated by code only. Ollama
  ([ollama.com](https://ollama.com)) is the local fallback and is not probed. The "Scripted attacker"
  model needs no key.
- **No token set** (none of the four above): the console and API are open and everyone is admin (demo mode).
  The CLI prints a warning. Set tokens for anything beyond a local demo.
- **Any token set:** the API and console need a valid token for reads as well as writes (see Operator API).

## Plants

Two plants share the code; each has its own SQLite file, scenarios and audit log.

| Plant | Story |
|---|---|
| **A** (Coastal Plant, default) | Sector 4 leak, a faulty pressure sensor, algal-bloom warning (the scenarios above) |
| **B** (Gulf Plant) | Sector 2 leak with a bypass loop and a school as the critical node; chlorine sensor `CL-S2` drifts then flatlines; early red-tide warning around 13:15; 18,000 m3 reservoir |

- **Files:** plant A uses `AQUAGRID_DB`; plant B uses `plant_b.sqlite` in the same folder.
- **Seeding plant B:** the web app builds a missing plant file the first time that plant is used, so there is
  nothing to run. To rebuild it by hand: `uv run python -c "from aquagrid import seed_data; seed_data.build('B')"`.
- **CLI:** `aquagrid.cli` works on plant A only.
- **Login:** the console asks for a token first. An admin token then shows a plant picker; a plant token goes
  straight into its plant. Admins can switch plant from the header.

## Command line

```bash
uv run python -m aquagrid.cli seed                       # (re)build the synthetic database
uv run python -m aquagrid.cli inspect peak_2pm           # sensor health and leak findings
uv run python -m aquagrid.cli run peak_2pm               # agent run with live trace and brief
uv run python -m aquagrid.cli run attack --attack        # replay the scripted malicious model
uv run python -m aquagrid.cli queue                      # pending approvals
uv run python -m aquagrid.cli approve 1 --operator sam   # also: reject, revert (prompts for token)
uv run python -m aquagrid.cli llm-check --provider groq  # does the provider call tools?
```

## Layout

```
frontend/           React + Vite + TypeScript operator console (src/, built to dist/)
aquagrid/web.py     FastAPI backend for the console (human gate lives here)
aquagrid/
  config.py         every threshold and env value, no logic
  schemas.py        Pydantic contracts (extra fields forbidden at the trust boundary)
  db.py             schema, connections, transactions, audit logging
  seed_data.py      synthetic network, telemetry with injected faults, scenarios
  guards.py         pure functions: sensor checks, leak classification, action guards
  tools.py          the two read-only tools and the state loader
  scheduler.py      tariff-aware production schedule
  gateway.py        the only write path: stage, approve, reject, revert
  agent.py          LLM loop, tool dispatcher, scripted attacker
  llm.py            OpenAI-compatible client with provider fallback chain
  view.py           presentation helpers for the console
  profiles.py       per-plant profile (name, reservoir, sectors, leak, scenarios); plants A and B
  live.py           guard-driven replay data for Mission Control
  cli.py            terminal demo and operator console (plant A only)
tests/              pytest suite (guards, gateway, agent, scenarios, demo numbers, app, cli)
PLAN.md             scope and design source of truth
```

## Operator API

`uvicorn aquagrid.web:app` serves the console and a JSON API (Swagger at `/docs`). When any token is configured,
**reads and writes both need the `X-Operator-Token` header**, plus `X-Plant: A|B` to pick the plant (default `A`).
Only `GET /api/health` and `POST /api/login` are open. With no token configured the API runs in unauthenticated
demo mode (everyone is admin), as the CLI does.

- `POST /api/login` with `{"token": "..."}` returns `{role, plants}` (`admin` or `plant`; the plants it may use).
- **401**: token missing or invalid. **403**: valid token, but not for the requested plant. **422**: unknown plant
  (or scenario/sector). A rejected write changes nothing.
- `/api/mission` also accepts `token` and `plant` query params, because the iframe cannot send headers. The token
  then appears in the URL (demo-grade; use a short-lived ticket if this ever ships). Write endpoints take the header only.

| Endpoint | Auth | Purpose |
|---|---|---|
| `GET /api/state`, `/api/actions?status=&run_id=`, `/api/runs/{id}`, `/api/runs/{id}/trace`, `/api/audit?run_id=&limit=` | token (read) | read-only views; `status=PENDING_APPROVAL` is the approval queue |
| `POST /api/scenario`, `/api/run`, `/api/fire` | token | load a scenario, run the agent, set the Civil Defence fire reserve |
| `POST /api/actions/{id}/approve`, `/reject`, `/revert` | token | the human gate: body `{operator, note}`; 409 if the action is not in the right state |
| `POST /api/stage-demo` | token | demo-only exception: queues a closure of the leak's isolating valve as `PENDING_APPROVAL`, through the same gateway and guards |

Nothing executes without a human approval: no endpoint approves automatically, and the LLM never reaches this API.

## Mission Control

The console has three tabs. **Mission Control** is a live replay (12:00 to 14:00) of the selected scenario: network map,
anomaly radar, agent feed, alarm list, sensor matrix and the energy-water ROI. Every figure comes from the same guards the
agent uses (`aquagrid/live.py`); the page itself is `aquagrid/mission/`, served read-only at `/api/mission` (token and plant via query params) and shown in a
sandboxed iframe. **Classic console** is the metrics, sensors, schedule and fire-reserve view. **Action required** is the
human approval gate; a floating popup appears whenever a proposal is waiting. Pick `attack` and press Run agent with
"Scripted attacker" to see the red security state.

The ROI panel shows the peak-tariff kWh the plan banks, the kWh the reserve floor blocked, the AED saved, and the energy
wasted by the Sector 4 leak, so savings are always shown next to the floor that limits them.
